# idlink

CLI для аудита собственных публичных профилей и объяснения возможных связей.
Python 3.11+, MIT. Каждый результат содержит процент, причины и контрдоводы;
максимальная формулировка — **«вероятно связаны»**.

Проект пока хранится приватно. Лицензия позволяет открыть исходники позднее.

## Установка и запуск

Python 3.11+, Git и доступ к репозиторию. Клонируйте из папки, где ещё нет `idlink`.
Если проект уже скачан, перейдите в папку с `pyproject.toml` и пропустите `git clone` и `cd idlink`.

### Linux

```sh
git clone https://github.com/tzr7ybdfky-dotcom/idlink.git
cd idlink
python3 -m venv .venv
./.venv/bin/python -m pip install .
source .venv/bin/activate
./.venv/bin/python -m idlink serve --repository-url https://github.com/tzr7ybdfky-dotcom/idlink
```

### macOS

```sh
git clone https://github.com/tzr7ybdfky-dotcom/idlink.git
cd idlink
python3 -m venv .venv
./.venv/bin/python -m pip install .
source .venv/bin/activate
./.venv/bin/python -m idlink serve --repository-url https://github.com/tzr7ybdfky-dotcom/idlink
```

### Windows (PowerShell)

```powershell
git clone https://github.com/tzr7ybdfky-dotcom/idlink.git
cd idlink
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install .
.\.venv\Scripts\python.exe -m idlink serve --repository-url https://github.com/tzr7ybdfky-dotcom/idlink
```

После активации окружения поиск в терминале: `idlink search USERNAME`.
В Windows используйте `.\.venv\Scripts\python.exe -m idlink search USERNAME`.

Откройте **http://127.0.0.1:8765**. Остановка: **Ctrl+C**.

## Веб-интерфейс и поиск по площадкам

Одно поле для ника, домена или почты: тип ввода определяется автоматически.
Все подходящие автоисточники проверяются сразу; каталог площадок свёрнут в дерево,
вдохновлённое [OSINT Framework](https://osintframework.com/).
Граф поддерживает масштабирование, перетаскивание узлов и разбор связей по клику.
Поиск следует одному уровню опубликованных ссылок на GitHub, Keybase, Hacker News
и стандартные handle Bluesky. Отсутствующий профиль не добавляется в граф;
ошибка источника показывается отдельно и не останавливает остальные проверки. Это локальное приложение;
автономный `report.html` показывает готовый результат, а новый поиск выполняется через сервер.

Каталог содержит **460 источников**. Для ника автоматически выбираются
**442 источника: 4 публичных API и 438 проверок страниц по правилам Sherlock**.
Капчи, 403/429, неизвестные редиректы и ошибки robots.txt не считаются отсутствием
профиля или успешной находкой. Запросы выполняются последовательно; полный проход
может занять много минут. В граф попадают URL-кандидаты с явным предупреждением:
правила отсутствия страницы — эвристика, а не подтверждение аккаунта или личности.
Исходные HTML, био и картинки этих проверок не сохраняются и не дают дополнительных сигналов.

Известные ограниченные площадки (включая Telegram, Instagram, Facebook, TikTok,
LinkedIn и Reddit) автоматически не проверяются. Для них остаются ручные ссылки;
такие ссылки не добавляют узлы и проценты. В Telegram адрес может вести на канал или бота.
[Условия Telegram](https://telegram.org/tos/content-licensing) запрещают scraping.

Публичные API Wikimedia реализованы и проверены на фикстурах, но отключены в каталоге:
проверка robots.txt 11 октября 2026 года запрещает выбранные `/w/api.php`.
GitLab, Habr и DEV Community также отключены до разрешённого способа доступа.
Условия и пригодность остальных правил не проверены индивидуально. Наличие правила
Sherlock не гарантирует разрешение доступа: перед использованием проверьте условия
выбранных площадок. Известные запреты внесены в блок-лист; robots.txt проверяется при запуске.

CLI тоже проверяет все разрешённые источники по одному нику:

```sh
idlink search YOUR_USERNAME
```

`search` по умолчанию использует `--platforms all`, `audit` — `auto`.
Успешный ответ API, отсутствие профиля и ошибка доступа различаются в отчёте.
Нет доступа ≠ нет аккаунта. Совпадение ника ≠ установленная личность.
Обычные соцсети не поддерживают гарантированный поиск человека только по нику.
Правила Sherlock могут устаревать и ошибочно принимать заглушку за профиль.
Для автоматизации новых площадок нужны правила детектирования и проверка условий доступа.

URL-шаблоны и GET-правила детектирования взяты из
[Sherlock](https://github.com/sherlock-project/sherlock) под MIT. Примеры реальных ников,
нестандартные заголовки, cookies и POST-запросы не импортированы.
Лицензия: `idlink/data/SHERLOCK-LICENSE`, происхождение: `catalog-provenance.json`.
Сервер слушает только `127.0.0.1`, не пишет историю запросов и не сохраняет исходные профили.
Один HTTP-клиент и ограничитель сохраняются между поисками; блокировка домена действует
до остановки сервера. Запросы из другого Origin и без токена страницы отклоняются.

## CLI

В папке проекта используйте `.venv/bin/python -m idlink` (Linux/macOS)
или `.\.venv\Scripts\python.exe -m idlink` (Windows) вместо `idlink` ниже.
Для `audit` добавьте `--repository-url https://github.com/tzr7ybdfky-dotcom/idlink`.

```sh
idlink audit YOUR_USERNAME --platforms github --out report.html
idlink search YOUR_USERNAME
idlink explain EDGE_ID --report report.html
```

`YOUR_USERNAME` — ник, `EDGE_ID` — ID ребра из вывода.
`audit` — режим по умолчанию; `search` проверяет все подключённые автоисточники.
`--purpose` необязателен в CLI; явно переданная цель должна быть непустой.
Коды выхода: 0 — успех, 2 — ошибка ввода, 3 — сеть или запрет доступа.

## Отчёт

Откройте `report.html` в браузере. D3 7.9.0, CSS и данные встроены в один файл:
CDN, картинок, шрифтов и внешних скриптов нет. CSP запрещает сетевые обращения страницы.
Толщина ребра равна `12 × probability`; проценты показываются на графе и в списке.
Клик открывает сигналы и контрдоводы. Список кнопок доступен с клавиатуры.
`explain` читает тот же HTML без выполнения JavaScript и без запросов в сеть.

При более чем 24 узлах в отчёте остаются только связи с оценкой ≥30%; все узлы
и статусы проверок сохраняются. Пунктир означает группировку наблюдений, без оценки личности.

Для знакомства есть `examples/demo.html` — все профили в нём синтетические.
Граф не делает транзитивных выводов: A↔B и B↔C не доказывают связь A↔C.

## Источники и ограничения

* **GitHub:** [публичный REST API](https://docs.github.com/en/rest/users/users#get-a-user),
  без токенов. Организации пропускаются. Био превращается в токены, ссылки — в URL.
  [Публичные события](https://docs.github.com/en/rest/activity/events#list-public-events-for-a-user)
  дедуплицируются по ID; payload, тексты, репозитории и временные отметки событий не сохраняются.
  API не даёт надёжного признака стандартного аватара: pHash GitHub не собирается.
* **Gravatar:** [официальный публичный endpoint изображений](https://docs.gravatar.com/sdk/images/).
  E-mail нормализуется и превращается в SHA-256; адрес не сохраняется.
  `d=404` исключает генерируемую картинку, `r=g` ограничивает доступный рейтинг.
  404 означает отсутствие доступного аватара, а не доказанное отсутствие аккаунта.
  Наблюдение аватара не объявляется существованием полноценного публичного профиля.
  Profile API с Bearer-аутентификацией не используется.
* **Bluesky:** [официальный публичный API](https://docs.bsky.app/docs/advanced-guides/api-directory),
  без авторизации. Ник `demo` проверяется ровно как `demo.bsky.social`, без перебора
  вариантов. Кастомные handle-домены не проверяются этим адаптером.
  400 `ProfileNotFound` означает отсутствие; другие ошибки не считаются отсутствием.
* **Hacker News:** [официальный API](https://github.com/HackerNews/API),
  точный ник с учётом регистра; доступны только пользователи с публичной активностью.
  Самоописание преобразуется в токены и ссылки, истории публикаций не собираются.
* **Keybase:** [официальный user/lookup](https://keybase.io/docs/api/1.0/call/user/lookup),
  только `basics,profile`; ключи, адреса кошельков и криптографические proofs не запрашиваются.
* **Wikimedia:** [MediaWiki Users API](https://www.mediawiki.org/wiki/API:Users)
  для Wikipedia EN, Wikidata и Commons; в текущем каталоге автоматические запросы отключены
  по robots.txt. Эти проекты используют общую систему аккаунтов: сигналы зависимы.
* **website:** публичная стартовая HTML-страница явно указанного домена;
  только meta description и ссылки `rel=me`, без копирования страницы или обхода сайта.
  Владелец домена не устанавливается. Для подключаемого домена предварительно проверьте ToS;
  адаптер не способен автоматически прочитать и юридически оценить условия всех сайтов.
* **Habr:** сетевой сбор отключён. [Соглашение](https://account.habr.com/ru/info/agreement)
  ограничивает несанкционированный сбор персональных данных и копирование контента.
  `--platforms github,habr` выдаёт явное сообщение о недоступности Habr и код 3.
  Альтернатива для активности — GitHub; для Habr нужно разрешение площадки.

## Скоринг: эвристика, не калибровка

```text
prior = 0.01
logit0 = ln(0.01 / 0.99)
posterior = sigmoid(logit0 + L_links + min(5.0, sum(other log_lr)))
```

| Сигнал | log_lr |
| --- | --- |
| Взаимные явные ссылки на адреса профилей | +6 |
| Односторонняя ссылка | +3 |
| pHash 64 бита: d ≤ 4; d 5–8; d ≥ 9 | +4; +1.5; 0 |
| Стандартный или отсутствующий аватар | 0 |
| Точный нормализованный ник; Jaro-Winkler ≥ 0.92 | +1 × rarity; +0.5 × rarity |
| Jaccard содержательных токенов ≥ 0.3 | +1 |
| Общий явный e-mail, домен или handle | +3 |
| ≥30 событий у обоих и cosine ≥0.9 | +0.5 |
| Преимущественно разные языки био | −1.5 |

Нормализация ника: lower, удалить `. _ -`; rarity = min(1, длина/12).
Для разных похожих имён используется меньшая длина — консервативный выбор.
Ник в списке частых у любого конца ребра подавляет вклад имени полностью.
Без положительного `links` результат дополнительно ограничен 85%.
При данной формуле лимит остальных сигналов фактически даёт максимум около 59.99% без links.
Взаимные ссылки без других сигналов дают **80.30%**: первоначальный критерий >85%
математически несовместим с prior=0.01 и +6. Реализация сохраняет заданную формулу.
Взаимные ссылки вместе с дополнительными сигналами могут дать >85%.

Вердикты: <30% «связь маловероятна», 30–60% «возможна», >60% «вероятно связаны».
Веса не обучены на размеченных данных. Зависимые сигналы, шаблонное био, общий домен,
скопированная картинка, языки и автоматизация легко дают ложное сходство.
«Редкие токены» здесь — слова длиной ≥3 без стоп-слов ru/en и общих терминов;
это фильтр, а не измеренная частотность. «Уникальный идентификатор» тоже эвристика:
частые сервисные домены исключены, но персональность оставшихся не доказана.
Язык определяется по доминирующему алфавиту и может ошибаться у многоязычного человека.

`data/common_usernames.txt` содержит **45 вручную выбранных исключений**, включая `alex`.
Это **не top-10000**: достоверный разрешённый частотный источник не предоставлен.
Не используйте списки из утечек. Расширяйте файл проверенными открытыми данными;
копия `idlink/data/common_usernames.txt` входит в wheel, тест проверяет совпадение файлов.

## Доступ, хранение и этика

Только публичные страницы и официальные открытые API, без логина, токенов и cookies.
Один общий ограничитель на процесс: не чаще одного запроса за 2 секунды на hostname.
robots.txt проверяется до ресурса; wildcard, `$`, специфичные User-Agent и Crawl-delay учитываются.
Более строгая задержка применяется консервативно ко всем доменам текущего запуска.
404/410 robots допускает доступ; недоступная/непригодная политика останавливает запрос.
403/429, Retry-After и исчерпанный лимит блокируют домен до конца запуска.
Капчи и редиректы не обходятся. Даже API robots.txt получает тот же rate limit и User-Agent:
`idlink/0.1.0 (+URL репозитория)`.

Не запускайте несколько процессов параллельно: межпроцессный rate limit не реализован.
HTTPS обязателен, локальные/приватные адреса отклоняются; DNS проверяется перед соединением.
Предварительная проверка DNS не гарантирует защиту от злонамеренного DNS rebinding.
Размер ответа ограничен 5 MB, изображения — 4 млн пикселей, таймаут HTTP — 20 секунд.

В `.cache/idlink` только URL, pHash (int/None), множество токенов, гистограмма и fetched_at.
E-mail из био превращается в хешированный токен; хеши не являются гарантией анонимности.
Изображения и исходные тексты профилей остаются только в памяти и не записываются.
Кэш имеет TTL 24 часа и не восстанавливает полный Profile: ссылки и default-флаг не хранятся.
CLI повторно запрашивает источники, чтобы не потерять важный links-сигнал из ограниченного кэша.
HTML — явно запрошенный результат с URL и объяснениями, не скрытый кэш профилей.

Не применяйте оценки для обвинений, преследования или решений о трудоустройстве,
кредитах и доступе к услугам. Не используйте утечки, закрытые данные, словари e-mail
или подбор адресов. Необязательный `--purpose` в CLI не делает любой поиск допустимым.

## Разработка и проверка

```sh
python -m pytest -q
python -m mypy --strict idlink tests
python -m ruff check .
python -m ruff format --check .
```

Тесты используют только синтетические данные, MockTransport и локальные фикстуры;
реальные подключения и DNS запрещены autouse-фикстурой.
GitHub Actions запускает проверки на Python 3.11, 3.12, 3.13 и 3.14.
Интерактивность отчёта проверена через localhost; в среде разработки прямое `file://`
открытие заблокировано инструментом браузера. Отсутствие внешних ресурсов проверяется тестами.
Условия площадок и формат API могут изменяться — перед обновлением адаптеров проверьте их снова.

D3 7.9.0 взят из пакета npm `d3`, распространяется по ISC;
его лицензия находится в `idlink/assets/D3-LICENSE` и встроена в каждый HTML.
