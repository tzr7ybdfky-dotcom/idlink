# Источники и проверка профилей

[← README](../README.md)

Каталог: 10198 записей; для ника выбираются 10163 автоматических источника.
Это число правил, а не гарантия доступности или точности всех площадок.

* **GitHub:** [публичный REST API](https://docs.github.com/en/rest/users/users#get-a-user),
  без токенов. Организации пропускаются. Био превращается в токены, ссылки — в URL.
  [Публичные события](https://docs.github.com/en/rest/activity/events#list-public-events-for-a-user)
  дедуплицируются по ID; payload, тексты, репозитории и временные отметки событий не сохраняются.
  API не даёт надёжного признака стандартного аватара: pHash GitHub не собирается.
* **Gravatar:** [официальный публичный endpoint изображений](https://docs.gravatar.com/sdk/images/).
  E-mail нормализуется и превращается в SHA-256; адрес не сохраняется.
  `d=404` исключает генерируемую картинку, `r=g` ограничивает доступный рейтинг.
  404 означает отсутствие доступного аватара, а не доказанное отсутствие аккаунта.
  Наблюдение аватара не объявляется существованием полноценного публичного профиля.
  Profile API с Bearer-аутентификацией не используется.
* **Bluesky:** [официальный публичный API](https://docs.bsky.app/docs/advanced-guides/api-directory),
  без авторизации. Ник `demo` проверяется ровно как `demo.bsky.social`, без перебора
  вариантов. Кастомные handle-домены не проверяются этим адаптером.
  400 `ProfileNotFound` или `InvalidRequest` с точным сообщением `Profile not found`
  означает отсутствие; другие ошибки не считаются отсутствием.
* **Hacker News:** [официальный API](https://github.com/HackerNews/API),
  API проверяет точный ник с учётом регистра; `search` может проверить до четырёх написаний; доступны только пользователи с публичной активностью.
  Самоописание преобразуется в токены и ссылки, истории публикаций не собираются.
* **Keybase:** [официальный user/lookup](https://keybase.io/docs/api/1.0/call/user/lookup),
  только `basics,profile`; ключи, адреса кошельков и криптографические proofs не запрашиваются.
* **Wikimedia:** [MediaWiki Users API](https://www.mediawiki.org/wiki/API:Users)
  для Wikipedia EN, Wikidata и Commons. Эти проекты используют общую систему
  аккаунтов: сигналы зависимы.
* **website:** публичная стартовая HTML-страница явно указанного домена;
  только meta description и ссылки `rel=me`, без копирования страницы или обхода сайта.
  Владелец домена не устанавливается. Для подключаемого домена предварительно проверьте ToS;
  адаптер не способен автоматически прочитать и юридически оценить условия всех сайтов.
* **Habr:** сетевой сбор отключён. [Соглашение](https://account.habr.com/ru/info/agreement)
  ограничивает несанкционированный сбор персональных данных и копирование контента.
  `--platforms github,habr` выдаёт явное сообщение о недоступности Habr и код 3.
  Альтернатива для активности — GitHub; для Habr нужно разрешение площадки.

## Проверка находок

HTTP 200 недостаточно: нужен признак запрошенного профиля. Обычная HTML-страница
дополнительно сравнивается с отрицательным контролем — случайным ником.
Публичный JSON с совпадающим ником и стабильным ID не требует этого контроля.
Заглушки, CAPTCHA, блокировки, таймауты и неясные редиректы не считаются находками.

В Telegram адрес может принадлежать человеку, каналу или боту. Отсутствие
публичного превью не доказывает отсутствие аккаунта.

## Происхождение

Поддерживаются шаблоны движков Maigret, включая форумы, вики и социальные серверы.
Импорт исключает отключённые сайты, зеркала, HTTP, POST, шаблоны поддоменов,
cookies, нестандартные заголовки и примеры пользовательских аккаунтов.

## Расширение каталога 14 октября 2026

Maigret: импортировано 6157 правил из снимка с 8144 записями; WhatsMyName: 267 новых правил.
Итог с исходным каталогом — 6893 записи, 6859 автоматических проверок по нику.
Часть правил относится к независимым серверам одного движка, а не к разным соцсетям.
Новые записи проверены тестами на синтетических ответах; полного сетевого аудита
всех новых площадок не было. Отчёт от 12 октября относится к прежнему каталогу.
На 14 октября порог 10000 источников ещё не был достигнут.

Discourse, Mastodon, Lemmy и MediaWiki проверяются по точному объекту аккаунта
с совпадающим ником и стабильным ID. Ссылки API остаются внутренними адресами проверки.
В результатах используются страницы аккаунтов; API-only источники без известной
публичной страницы отключены. Повторяющиеся адреса проверяются один раз.
Для Minecraft ссылка ведёт на публичную страницу игрока NameMC, стороннего каталога.

Повторный импорт локальных снимков из корня проекта:

```bash
python -m tools.import_catalog /path/to/maigret-data.json
python -m tools.import_whatsmyname /path/to/wmn-data.json
```

Сначала обновляйте Maigret, затем WhatsMyName: второй импорт исключает повторы из первого.

## Расширение 15 октября: независимые серверы Fediverse

Серверы обнаружены через публичный список узлов Mastodon, затем проверены напрямую.
Это отдельные серверы с собственными базами аккаунтов, а не 3300 разных социальных сетей.
Публичные метаданные сервера должны соответствовать его домену. Проверка случайного
несуществующего аккаунта должна вернуть структурированный `Record not found` с HTTP 404.
Если сервер публикует контактный аккаунт, дополнительно проверяются его ник, ID и
прямая ссылка на профиль. Имена контрольных аккаунтов и данные профилей не сохраняются.

[Происхождение и счётчики проверок](../idlink/data/fediverse-provenance.json) ·
[Метаданные серверов](../idlink/data/fediverse_servers.json) ·
[CC0 для собранных фактов](../idlink/data/FEDIVERSE-LICENSE).

В [полном CSV](catalog-audit.csv) есть строка для каждого источника. Тест проверяет,
что CSV совпадает с каталогом по ID, URL и признаку автоматического поиска.
Архивные проверки отделены от свежих; отсутствие сетевого теста помечается `not_tested`.

Воспроизведение (команда discovery выполняет сетевые запросы):

```bash
python -m tools.discover_fediverse peers.json --out verified.jsonl --target 3300 --live
python -m tools.import_fediverse verified.jsonl
python -m tools.render_catalog_audit --inventory --out docs
```

`peers.json` — JSON-массив доменов из `https://mastodon.social/api/v1/instance/peers`.
После обновления файлов переустановите пакет: `python -m pip install .`.

## Российские социальные площадки

В `--social` доступны VK, Одноклассники, Rutube, Дзен, Пикабу, Boosty,
LiveJournal и варианты Мой Мир. Существующие ID импортированных источников сохранены.
Rutube также включён в `--video`, Дзен — в `--blogs`.

Новые короткие имена источников: `ok`, `ok-id`, `rutube`, `rutube-id`, `dzen`.
`ok` проверяет короткий адрес, `ok-id` — числовой ID профиля
([форматы ссылок ОК](https://ok.ru/help/kak-skopirovat-ssylku-na-profil)).
`rutube` проверяет короткий адрес канала, `rutube-id` — числовой ID в `/channel/`.
Короткие адреса доступны не всем каналам
([справка Rutube](https://rutube.ru/info/verification/)). Поиск по нику не определяет
числовой ID автоматически; для ID укажите отдельный источник.

Новые правила требуют совпадающий `og:url`, непустой `og:title` и отрицательный
контроль со случайным адресом. Контроль обязан вернуть 404/410 или явный текст
отсутствия страницы. Числовые ID проверяются с числовым контрольным адресом.
Это эвристики публичных страниц, а не подтверждение личности. Если сайт отдаёт
только JavaScript-оболочку, требует вход или не подтверждает отсутствие контрольной
страницы, результат остаётся непроверенным. Регрессионные проверки выполняются
на синтетических HTTP-ответах; доступность живых площадок не гарантируется.
